## Requirements

### R1. Профессиональный UI/UX без визуального шума («Anti-Slop Design»)
- Разработать интерфейс дашборда в строгом инженерном стиле (в духе Linear/GitHub/Vercel): нейтральная сбалансированная палитра, четкая типографика, аккуратные тонкие границы (1px border), мягкие тени.
- Полный запрет на «нейрохрючево»: никаких кислотных радужных градиентов, никакой избыточной аляповатой анимации и никаких emoji в качестве интерфейсных иконок. Все иконки должны быть чистыми векторными SVG (Lucide/Feather/Heroicons стиль).
- Карточки предметов и единый сквозной список заданий:
  - Мгновенная визуальная дифференциация статусов: «Нужно сделать», «На проверке у преподавателя», «Оценено / Сдано».
  - Быстрый просмотр описания/ТЗ задания и ссылок на прикрепленные файлы методичек без необходимости блуждать по старым переходам.
  - Возможность в любой момент переключиться на оригинальный табличный вид сайта.

### R2. Бесшовный автологин и надежный Keep-Alive сессии
- Реализовать фоновый сервис-воркер, который регулярно отправляет лёгкие keep-alive запросы к `xiais.kemsu.ru` и `eios.kemsu.ru`, предотвращая таймаут сессии на стороне сервера Tomcat/nginx.
- Автоматический вход: скрипт распознает форму входа на `eios.kemsu.ru/main`, корректно эмулирует ввод учетных данных (с учетом синтетических событий React) и подтверждает вход.
- Самовосстановление: при обнаружении ошибки протухшей сессии (`Нет доступа! java.lang.NullPointerException` на `xiais.kemsu.ru`) расширение бесшовно переавторизует пользователя через SSO и возвращает на рабочий стол.

### R3. Синхронизация задач с TickTick Open API
- Интеграция с официальным API TickTick (`https://api.ticktick.com/open/v1`):
  - Одиночная отправка задания кнопкой у каждой лабы.
  - Пакетная синхронизация («Синхронизировать все активные дедлайны»).
- Точный парсинг дедлайна (с сохранением даты и времени до минут) и установка `dueDate` в задаче TickTick.
- Форматирование задачи: название с префиксом предмета, описание со статусом и ссылкой, теги (`#КемГУ`, `#Лаба`), автоматическое определение/создание проекта «КемГУ / Учёба».
- Локальная дедупликация в хранилище расширения для предотвращения дублирования ранее отправленных задач.

### R4. Слепое рецензирование (Blind Review) и верификация логики
- Провести независимый аудит реализованного кода и дизайна отдельным агентом-рецензентом без предвзятости:
  - Проверка соответствия дизайн-стандартам (отсутствие эмодзи, чистота CSS, консистентность отступов и шрифтов).
  - Проверка надежности работы с DOM legacy-портала (экранирование, устойчивость к изменению структуры таблиц).
  - Тестирование обработки сетевых сбоев TickTick и невалидных токенов.

- [ ] Цветовая схема выдержана в нейтральных тонах с акцентными функциональными цветами для статусов (сдержанный зеленый/желтый/красный).
- [ ] Реализованы фильтры по статусам заданий («Все», «Надо сделать», «На проверке», «Оценено») и живой поиск по названию лабы/предмета.
- [ ] Присутствует кнопка быстрого переключения между новым UI и оригинальным интерфейсом ИнфоОУПро.

- [ ] Фоновый воркер `background.js` зарегистрирован в Manifest V3 и выполняет периодические keep-alive пинги через `chrome.alarms`.
- [ ] Автологин на `eios.kemsu.ru` корректно заполняет поля ввода и сабмитит форму, не зацикливаясь при неверных данных.

- [ ] Повторное нажатие на синхронизацию задачи не создает дубликат.

### Архитектура и аудит (Blind Review)
- [ ] Расширение успешно загружается в Google Chrome в режиме разработчика без ошибок манифеста или CSP.
- [ ] Код прошел слепое рецензирование на предмет чистоты логики, отсутствия гонок асинхронных вызовов и качества UI.
